# 项目现状总结

> 面向：接手者 / 复盘 / 面试准备。
> 核对时间：2026-09-27。**所有数字与状态均为实测核实，不是照抄计划文档。**

---

## 一、这是什么

一个银行影像（银行卡 / 身份证）审核测试平台。平台侧是确定性的 FastAPI 服务
（OCR → 质量检测 → 字段解析 → 规则审核 → 落库），在此之上叠了一层
**独立进程的 AI 能力层**，做审核解释、知识客服、规则+LLM 双判。

**真正的立意**不在审核业务本身（那部分是确定性的，传统接口测试就够），
而在于回答一个问题：**一个会调工具、多步决策、输出不确定的 AI 系统，要怎么测。**

### 关键能力

**审核 Agent**（`ai_service/agent.py`）
- 4 个白名单工具，参数在派发**之前**校验
- 三重预算（步数 / token / 工具调用），7 种停止原因，超预算标记而非抛异常
- **转人工硬规则在两条路径上都执行** —— 模型（或被注入的模型）回 `finish` 也绕不过
- 有模型走 LLM，无模型走确定性路径，**输出结构完全一致**

**知识客服 Agent**（`ai_service/knowledge/`）
- 两道闸门：**出口闸门**（越界根本不进 LLM）+ **接地闸门**（无来源的断言一律拦）
- 意图判定是**纯规则表**，不用分类器 —— 安全闸门要可解释、可复现
- 拒答话术是产品决定，写在代码里并被测试断言

**双判**（`app/adjudication.py` + `ai_service/adjudication.py`）
- 核心不变式：**规则拥有否决权，LLM 只有有限的放行建议权**
- `Literal["review","pass"]` 让模型**结构上产不出** `reject`
- 业务层 `apply_adjudication` 再兜一层，绝不 `return ai_decision`
- 任何失败（不可用 / 超时 / 输出非法 / 异常）都回落规则原判

**评测**（`ai_service/eval/`）
- golden 集 40 条，人工结论标注（署名 `jb（开发）`）
- 评测**调用平台真实规则引擎**，测的是平台而非占位符
- 四层指标 + 回归门禁 + 指标方向注册表（漏登记会被检测出来）

## 四、实测数字（全部真实跑过）

### 真实 PaddleOCR（100 张合成银行卡）

| 指标 | 值 |
| --- | --- |
| 推理成功 | 100 / 100 |
| 卡号 / 姓名 / 有效期准确率 | **均 100%** |

⚠️ **必须连前提读**：合成集不含透视畸变、传感器噪声、JPEG 压缩、重拍，
比真实证件照**简单得多**。它证明「链路通、字段解析对」，
**不代表真实证件场景的识别率**。

### 真实模型 golden 评测（deepseek-chat，40 条）

| 指标 | 离线 | 真实模型 |
| --- | --- | --- |
| 工具序列完全匹配 | 1.0 | **0.225** |
| 工具集合覆盖（顺序无关） | 1.0 | **0.925** |
| 解释层 相关性/准确性 | 5.0 / 5.0 | **4.38 / 2.45** |
| 结论正确率（人工标注） | 0.775 | 0.775 |
| 平均 token | 0（不调模型） | **3538** |

**两个重要解读**：

1. **离线那套 5.0/5.0 偏高** —— 确定性 judge 打的是同源模板文本，接近同义反复。
   真实模型 2.45 **更低也更可信**。
2. **工具序列 1.0 → 0.225 是指标问题，不是模型问题** ——
   模型选的是**同一组三个工具**，只是后两个顺序不同。
   顺序严格匹配 0.167 vs 集合匹配 0.917，差这么远说明顺序不是有效信号。
   已新增 `tool_set_accuracy`（顺序无关）。

## 五、没做的 / 有问题的

### A. 唯一剩下的开发项

| 项 | 说明 |
| --- | --- |
| **P4b MCP server** | 把审核/客服能力暴露为 MCP 工具。**完全没做**，仓库搜 `FastMCP` 零匹配 |

### B. 被数据缺口卡住的两项（**不应继续调参**）

**反光严重度阈值启用** 与 **双判改判正确性的验证** 都需要同一个信息：
**图像究竟还能不能读**。

而当前评测集里 `fields` 是 labels.json 的**标注真值**、不是 OCR 实际输出，
所以「字段全部解析成功」恒成立，这个信号没有区分度。

后果很具体：模型据此放行反光样本时，**看起来像判断失误，实际是评测集的产物**。

**推进条件**：让 `fields` 来自真实 OCR 输出，或引入真实证件照片。
**在此之前这两项不该继续调参** —— 调了也无法验证对错。

### C. 对外化的三条上线阻塞项（已核实，未做）

| # | 风险 | 核实方式 | 结果 |
| --- | --- | --- | --- |
| R1 | **无认证** | `grep -c Depends ai_service/knowledge/api.py` | **0** |
| R2 | **无限流** | 全仓库搜 rate limit/quota | **零匹配** |
| R3 | **响应含内部信息** | 实跑看响应字段 | `trace` + `rejected_answer` 都在 |

另有 R4–R8（注入加固、语料可引性审查、产品话术签核、输出侧 PII 扫描、审计留痕）。

**没做的理由**：不属于「可选评估」的定位；其中 R5/R6 需业务/合规签核，
不是技术单方可决。

### D. 已知的自我诚实清单（都在 README 里）

- **judge 校准集是占位标注** —— 管线可用，**数字暂无统计意义**
- **离线解释层分数偏高** —— 确定性 judge 打同源文本，接近同义反复
- **SQLite 是单写者** —— 无 WAL，不适合生产并发
- **合成数据不等于真实分布** —— 所有 OCR/图像相关结论都受此限制
- **真实模型只跑过一轮、只试过一个模型** —— 单次采样不足以断言稳定性

### E. 小瑕疵

- `ai_service/llm.py` 的 `DEFAULT_ANTHROPIC_BASE_URL = "the service endpoint"`
  是**占位字符串**，不是真 URL（Anthropic 路径需显式配 `LLM_BASE_URL`）

## 六、诚实的自我评价

### 强的地方

1. **测试工程水准远超作品集平均** —— 1052 个测试，且**类型对**：
   对抗、故障注入、安全不变式、边界排他性，不只是 CRUD 覆盖
2. **控制流的安全设计成熟** —— 「规则否决 / LLM 有限放行」+ 结构约束 + 业务层兜底
3. **度量基础设施有护栏** —— 指标方向注册表、未登记指标检测、浮点容差
4. **罕见的自我诚实** —— README 详细列了自己的缺口，包括「哪些数字不可信」

### 弱的地方

1. **OCR 从未处理过真实证件** —— 100% 合成，无透视/噪声/压缩
2. **AI 能力几乎没在真实模型上验证** —— 全部测试与 CI 都是离线的
3. **指标部分在测自己** —— 确定性 judge 打同源文本
4. **外围工程从零开始** —— 认证/限流/审计都没有

### 一句话

> 这是一个**高质量的 AI 测试平台仿真**：工程craft与测试思维的真实展示，
> 但**不是** OCR 效果或 AI 能力的真实展示。
> 对「Agent 测试开发」岗是真实资产；对「AI 应用开发」岗，
> 面试官会立刻要那个它拿不出来的东西 —— 真实数据 + 真实模型行为。
