# CTE 主动测试演进：方案审核与实施边界

审核日期：2026-09-28。依据用户提供的方案，先审核，再实施。

## 审核结论

采用 P5 知识层迭代：已验证经验 → 独立模型预测 → 冻结 → 执行 → 独立 Oracle → 经验候选 → 人工晋级 → 后续检索。
本阶段不训练模型、不实现自动修复或发布、不引入多 Agent 编排或向量数据库。

必须修正的六项：

1. 旧 `blind_predict()` 把 `event.expected_result` 复制成预测，且事件带有历史结果。它是历史预期回放，不是 LLM 盲预测；保留历史证据，但不得纳入新盲预测指标。
2. O1–O6 表示答案来源，不是自动可信等级。已有测试也可能错误；参考实现与变形关系默认只能报告疑似差异。人工确认为 O3 后才能算确认缺陷。O6 永远不能独立确认缺陷。
3. 亮度 +5% 不保证 OCR 文本不变，尤其在阈值附近、饱和或随机推理时。第一版提供受限文本变形探针；图像扰动暂不作为硬断言。
4. Oracle 的期望规则在执行前冻结，Evaluator 可以看执行结果，但不接收 Predictor 的理由、概率或预测结论。
5. FPR = FP / (FP + TN)，与“预测有 Bug 的样本中有多少误报”不同。后者另报 false discovery rate。无有效分母输出 null；未知结论不当作正确或错误。
6. 历史回归不能证明泛化；模型自报置信度不是校准概率；失败样本数量不是独立缺陷族数量。未经人工分族确认的新缺陷族数报告 null。

## 第一版实现

- 单进程编排，独立无会话模型请求；复用 `ai_service.llm`。
- 预测只能产生 JSON 测试输入，受限执行器只调用注册函数，不执行生成的 Python 或 shell。
- 固定支持银行卡号、有效期和身份证字段解析；业务主链路不改变。
- Predictor 输入显式白名单：需求、当前代码、受限输入格式、verified 经验、同轮次之前的学习反馈。不传当前标签、实际结果或历史完整事件。
- 独立保存冻结包与执行证据，哈希绑定代码、Oracle、模型、预算、经验快照和候选输入；比较结果写新文件。
- 经验候选与验证经验分目录；确认和反证都可以成为有证据的经验，默认检索只读人工晋级且未失效的记录。
- 修订以新版本表示 specialize/generalize/merge/add_counterexample；旧版本追加 superseded/invalidate 事件，不改写历史。
- O4/O5 疑似结论、O6、环境错误和不可复现结果不能自动晋级。
- 无记忆与 RAG 使用相同模型和每次调用预算，固定经验快照；两组预测均冻结后才执行。报告实际 token 来源与成本代理，不把估算当 provider 账单。
- holdout 不提供学习反馈，不能晋级或进入经验库；按 group 排除近亲经验。数据作者仍需负责语义去重和跨组泄漏审查。

## 验收标准

必须测试：答案/理由隔离、先冻结后执行、拒绝篡改、O6 不确认、O5 只报疑似、错误不算缺陷、重复不充当新发现、未晋级不检索、反例可追踪、holdout 禁止学习、指标分母正确、无模型不假装 AI。

离线测试只能证明工程契约与执行链路；真实模型可用性与“经验提高未知缺陷发现率”分别需要 live 调用和独立实验，不预填提升百分比。

隔离是受限 API 和输入数据的工程边界，不是对有本机文件修改权限的用户提供安全隔离。审批绑定证据摘要，但本地署名不是身份认证系统。
